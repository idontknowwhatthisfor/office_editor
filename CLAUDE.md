# OfficeEditor

Free, offline Android viewer/editor for PDF, DOCX, XLSX and PPTX (view-only). The product spec and
milestone order (M0–M8) are in `PRD — Android Office Editor (DOCX, PDF, XLSX, PPTX).md`; work one
milestone at a time.

## Architecture

Native Kotlin shell + bundled web viewers in a WebView (PRD §5.1).

- `app/` — Kotlin + Jetpack Compose shell, package `com.officeeditor`.
  - `MainActivity` — home: recent files, "Open file" (SAF picker).
  - `ViewerActivity` — one document; also the target of "Open with" (`ACTION_VIEW`) and share-to
    (`ACTION_SEND`). Top bar is native; everything below it is the WebView.
  - `DocumentWebView.kt` — WebView setup and the JS bridge (`window.OfficeBridge`).
  - `Documents.kt` (format detection), `RecentFiles.kt` (SharedPreferences). Files lent by
    another app ("Open with") lose their access when the viewer closes, so the recent list keeps
    a private copy of those in `files/recent/`; picker files use a persisted URI permission.
- `web/` — Vite + TypeScript app, built into `app/src/main/assets/web` (git-ignored).
  - `src/main.ts` asks the bridge which document is open, fetches its bytes and loads that
    format's viewer as a separate chunk.
  - `src/pdf/` — PDF viewer on PDF.js (`pdfjs-dist`, legacy build). Editing (M5): `editor.ts`
    (tools, form inputs over the page, undo), `edits.ts` (the edit model, in PDF space),
    `write.ts` (pdf-lib: highlights, underlines, ink and text become real annotations with
    their own appearance streams; signatures are drawn into the page; form values get fresh
    appearances; page rotation/deletion).
  - `src/docx/` — read-only Word viewer in page layout, as Word shows it. `docx-preview` renders
    the XML to HTML; `paginate.ts` splits it into pages (docx-preview only breaks at explicit
    page breaks); `viewer.ts` corrects line spacing, fills page numbers and scales pages to the
    screen with a transform. `fonts.css` (generated by `scripts/make-docx-fonts.mjs`) aliases
    Times New Roman / Arial / Calibri to metric-compatible open fonts, since Android has none of
    them. The PRD's mammoth.js was dropped for viewing (it discards sizes, colours, alignment).
  - `src/xlsx/` — read-only spreadsheet viewer. `workbook.ts` reads the zip's XML itself (jszip +
    DOMParser): cached formula results, styles, theme colours, widths, merges, frozen panes.
    Formulas are not recalculated; Excel saves their results. `format.ts` applies number formats
    with `ssf`; `viewer.ts` draws only the cells near the screen, keeps headers and frozen panes
    with `position: sticky`, and does its own pinch-zoom (CSS `zoom`; page zoom is turned off).
    SheetJS CE was not used (its npm build is stale and reads no styles), nor ExcelJS (large,
    needs Node polyfills). Column widths use Excel's digit width of the default font
    (`DIGIT_RATIO`), checked against Mac Excel.
  - `src/pptx/` — read-only presentation viewer, drawn by our own code (pptx-preview, the PRD's
    candidate, ships only minified code with no source or licence file). `deck.ts` loads
    slide → layout → master → theme; `render.ts` draws a slide as HTML (shapes as SVG outlines
    from `geometry.ts`, text as HTML from `text.ts`, tables from `table.ts`), following
    placeholder inheritance and theme style references (`p:style`). `viewer.ts`: one slide per
    screen with scroll-snap, thumbnails, its own pinch/double-tap zoom. Charts, and SmartArt
    without a saved drawing, show a placeholder and a notice.
  - `src/ooxml.ts` — zip/XML/relationship helpers shared by the XLSX and PPTX readers.
- `test-files/` — sample documents; `make_samples.py` regenerates the synthetic ones.
  `make_xlsx_samples.applescript` builds XLSX samples with Microsoft Excel itself (installed on
  this Mac); `excel_text_dump.applescript` prints the text Excel displays per cell, to compare
  with the viewer's formatting. `make_pptx_sample.py` (python-pptx) + `pptx_resave.applescript`
  and `make_pptx_native.applescript` make decks that PowerPoint has saved, plus PowerPoint's PDF
  of each as the reference rendering. PowerPoint asks once for access to `test-files/`.

**How edits are saved:** the shell owns the Save button and dialog (`ViewerActivity`); an editor
reports unsaved changes with `OfficeBridge.setDirty`. On Save the shell calls
`window.officeSave(mode)`; the editor builds the file, re-reads it, and streams it back in base64
chunks (`web/src/save.ts` → `beginSave`/`writeChunk`/`finishSave`). `Saving.kt` writes it to a
temporary file, checks the format's signature, then either replaces the original (backing it up
first and restoring it if the write fails) or saves a copy through the system's save picker and
reopens the copy. Files lent read-only ("Open with") can only be saved as a copy. In a desktop
browser there is no shell: the editor offers a download instead.

**How bytes reach the viewer:** not through the bridge. The document is served at
`https://appassets.androidplatform.net/doc/current` and the page `fetch()`es it. The bridge only
returns metadata (`getDocument()` → `{name, format, mime, size, url}`). The URL honours HTTP
`Range`, and the PDF viewer reads through it in 256 KB pieces, so large PDFs aren't held in
memory whole. Quirk: for a Range request the WebView skips to the range start itself but reads
to the end of the stream it is given; see `EndingAt` in `DocumentWebView.kt`.

## Rules that come from the PRD

- No `INTERNET` permission, no network requests, no analytics. The WebView refuses every URL that
  isn't served by the app itself.
- No AGPL or commercial-only dependencies. Record each new library's licence.
- User-visible strings exist in English and Indonesian: `res/values` + `res/values-in` for native,
  `web/src/i18n.ts` for web.
- Never overwrite an original file until the new one is written and re-parsed (applies from M5).

## Build and run

Gradle needs a JDK it supports; the system default (27) is too new, so use Android Studio's:

```bash
export JAVA_HOME="/Applications/Android Studio.app/Contents/jbr/Contents/Home"
./gradlew :app:installDebug && ./gradlew --stop
```

`preBuild` runs `npm run build` in `web/` (needs `npm ci` there once, and `npm` on PATH).

Web-only iteration in a desktop browser, with a file picker instead of the bridge
(`.claude/launch.json` has the same server as `web-viewers`). In dev, `?file=` opens a file
directly, e.g. `http://localhost:5173/?file=/@fs/<repo>/test-files/sample.docx`:

```bash
cd web && npm run dev
```

Device debugging:

```bash
adb logcat -s OfficeEditorWeb          # the web viewers' console output
adb shell am start -a android.intent.action.VIEW -t application/pdf \
  -d "content://..." com.officeeditor  # simulate "Open with"
```

The WebView is inspectable from `chrome://inspect` in debug builds.

If `adb install` fails with `INSTALL_FAILED_VERIFICATION_FAILURE`, Play Protect rejected the build
and hid its prompt (the installer is `adb`). The owner has to allow it on the phone (Developer
options → "Verify apps over USB"); don't change that setting from here.
