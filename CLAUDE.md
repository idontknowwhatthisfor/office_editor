# OfficeEditor

Free, offline Android viewer/editor for PDF, DOCX, XLSX and PPTX (view-only). The product spec and
milestone order (M0–M8) are in `PRD — Android Office Editor (DOCX, PDF, XLSX, PPTX).md`; work one
milestone at a time.

## Architecture

Native Kotlin shell + bundled web viewers in a WebView (PRD §5.1).

- `app/` — Kotlin + Jetpack Compose shell, package `com.officeeditor`.
  - `MainActivity` — home: recent files, "Open file" (SAF picker), and "+" → New document / New
    spreadsheet: the system save picker creates the file, it is filled from a blank template
    (`res/raw/blank_document.docx`, `blank_spreadsheet.xlsx`, built by
    `app/templates/make_blank_templates.py`: A4, Calibri 11, no author metadata), and opened with
    `EXTRA_START_EDITING` (passed to the page as `edit` in `getDocument()`; a Word file then opens
    in edit mode).
  - `ViewerActivity` — one document; also the target of "Open with" (`ACTION_VIEW`) and share-to
    (`ACTION_SEND`). Top bar is native; everything below it is the WebView.
  - `DocumentWebView.kt` — WebView setup and the JS bridge (`window.OfficeBridge`).
  - `AboutActivity` — About & licences (ⓘ on the home screen): version, privacy note, and every
    bundled component's licence text, read from `assets/web/licences.json`. That file is built
    by `web/scripts/collect-licences.mjs` (runs before every web build) from the installed
    packages; add any new runtime dependency to its lists.
  - `Documents.kt` (format detection), `RecentFiles.kt` (SharedPreferences). Files lent by
    another app ("Open with") lose their access when the viewer closes, so the recent list keeps
    a private copy of those in `files/recent/`; picker files use a persisted URI permission.
- `web/` — Vite + TypeScript app, built into `app/src/main/assets/web` (git-ignored).
  - `src/main.ts` asks the bridge which document is open, fetches its bytes and loads that
    format's viewer as a separate chunk.
  - `src/pdf/` — PDF viewer on PDF.js (`pdfjs-dist`, legacy build). Editing (M5): `editor.ts`
    (tools, form inputs over the page, undo), `edits.ts` (the edit model, in PDF space),
    `write.ts` (pdf-lib: highlights, underlines, ink and text become real annotations with
    their own appearance streams; signatures are drawn into the page; form values get fresh
    appearances; page rotation/deletion).
  - `src/docx/` — read-only Word viewer in page layout, as Word shows it. `docx-preview` renders
    the XML to HTML; `paginate.ts` splits it into pages (docx-preview only breaks at explicit
    page breaks); `viewer.ts` corrects line spacing, fills page numbers and scales pages to the
    screen with a transform. Its bottom bar is the PDF viewer's (`src/pagebar.ts`: page indicator,
    thumbnails, search, edit); `search.ts` highlights matches with the CSS Custom Highlight API,
    and thumbnails are scaled copies of the pages. `fonts.css` (generated by `scripts/make-docx-fonts.mjs`) aliases
    Times New Roman / Arial / Calibri to metric-compatible open fonts, since Android has none of
    them. The PRD's mammoth.js was dropped for viewing (it discards sizes, colours, alignment).
  - `src/xlsx/` — read-only spreadsheet viewer. `workbook.ts` reads the zip's XML itself (jszip +
    DOMParser): cached formula results, styles, theme colours, widths, merges, frozen panes.
    Formulas are not recalculated; Excel saves their results. `format.ts` applies number formats
    with `ssf`; `viewer.ts` draws only the cells near the screen, keeps headers and frozen panes
    with `position: sticky`, and does its own pinch-zoom (CSS `zoom`; page zoom is turned off).
    SheetJS CE was not used (its npm build is stale and reads no styles), nor ExcelJS (large,
    needs Node polyfills). Column widths use Excel's digit width of the default font
    (`DIGIT_RATIO`), checked against Mac Excel.
  - `src/docx/editor.ts` — Word editing (M7), in place on the file's own XML. The edit view is
    docx-preview's rendering on real-size paper, scaled to the screen like the viewer (pages not
    split); a copy of document.xml gets
    a bookmark before every paragraph and run so the screen maps back to XML elements. Only
    paragraphs the user changed are rewritten (from their original pPr/rPr); others stay byte
    for byte. Paragraphs holding anything but plain text runs are locked. Bold/italic/underline
    are read back from computed styles; alignment, heading style and bullets/numbering are
    paragraph properties (missing heading styles and list definitions are added).
  - `src/xlsx/edit.ts` + `calc.ts` — spreadsheet editing (M6). `calc.ts` is our own formula
    engine (parser, ~120 common functions, reference shifting); it matched Excel on every
    formula of both sample workbooks. `edit.ts` keeps all sheets in memory, recalculates the
    dependents of an edit, inserts/deletes rows and columns (shifting formulas, merges, ranges in
    every sheet), undo/redo, and writes back into the sheet XML: values as inline strings,
    `fullCalcOnLoad` set, `calcChain.xml` removed. Formulas with functions it lacks keep Excel's
    value. Sheets with Excel tables can't have rows/columns inserted (would break the table).
  - `src/ui.ts` — dialogs, menus, toast (used by the spreadsheet editor), and the font size
    picker every editor uses (`fontSizeMenu`, `FONT_SIZES`). Font size: Word and PowerPoint wrap
    the selected text in a `data-sz` span (or mark the paragraph, with only a caret; a selected
    PowerPoint box changes all its text) and write `w:sz`/`w:szCs` (half-points, rPr in schema
    order) or `a:rPr sz` (1/100 pt); Excel adds a font and a cellXfs entry per (base format,
    size) to styles.xml and raises row heights; PDF text boxes take a size in points.
  - `src/pagebar.ts` — the bottom bar shared by the PDF and Word viewers.
  - `src/print.ts` — "Export as PDF" (⋮ menu, Word/Excel/PowerPoint). The shell loads the saved
    file a second time in a hidden WebView with `print` set (`Printing.kt`); the page lays it
    out for paper (`printDocx`: the paginated pages; `printXlsx`: each sheet's used range on A4,
    scaled to the width, no gridlines; `printPptx`: slides centred on landscape A4) and calls
    `OfficeBridge.printReady(w, h)`; the shell opens Android's print dialog, whose "Save as PDF"
    writes the file. Android's PDF printer only takes standard paper sizes. Scale print layouts
    with CSS `zoom`, not a transform: the print engine shrinks the whole document to fit an
    element's unscaled width. Dev: `&print` shows the layout, and headless Chrome
    (`--headless=new --print-to-pdf=out.pdf <url>`) prints it as the phone does.
  - `src/pptx/` — read-only presentation viewer, drawn by our own code (pptx-preview, the PRD's
    candidate, ships only minified code with no source or licence file). `deck.ts` loads
    slide → layout → master → theme; `render.ts` draws a slide as HTML (shapes as SVG outlines
    from `geometry.ts`, text as HTML from `text.ts`, tables from `table.ts`), following
    placeholder inheritance and theme style references (`p:style`). `viewer.ts`: one slide per
    screen with scroll-snap, thumbnails, its own pinch/double-tap zoom, and Present (beside the
    edit pencil): full screen on black, tap right/left to go on/back. In the app the page calls
    `OfficeBridge.setPresenting(true)` and the shell hides its top bar and the system bars and
    turns landscape; Back calls `window.officeEndPresentation()`. In a browser: Fullscreen API. SmartArt without a
    saved drawing, and charts `src/chart/` can't draw, show a placeholder and a notice.
  - `src/pptx/editor.ts` — PowerPoint text editing (M9), in place on each slide's XML. Edit mode
    renders slides with marks (`renderSlide(…, {edit})`: `data-sp` per editable shape, `data-p`,
    `data-r`) and the Deck keeps one working XML per slide (`keepSlides`). Typing, Enter and
    joins only change the screen; after a pause a box's paragraphs are rebuilt into the XML
    (unchanged ones copied, changed ones from their pPr/rPr/endParaRPr). Leaving a box fits its
    text (normAutofit shrink steps / spAutoFit height, measured offscreen) and redraws the slide.
    Never redraw while a box is being typed in: Android keyboards compose words, and changing the
    DOM mid-composition puts the word back in the wrong place (Enter waits for `compositionend`).
    Locked: paragraphs with fields or links, tables, charts, SmartArt. Only changed slides are
    written; their root start tag is kept as in the original.
    `shapes.ts` moves and resizes (part of M11): edit mode marks the slide's top-level elements
    `data-el` (`topShapes()`); the first tap selects one (no caret, so the keyboard doesn't push
    the slide away), a second tap on its text types; a drag on the selected element moves it, a
    handle resizes it (opposite corner fixed, rotation-aware; picture corners keep the ratio).
    Writes `off`/`ext` (a move only shifts `off`; a placeholder that inherits its position gets
    its own `a:xfrm`; a group's `chOff`/`chExt` stay, so its children scale). Tables move only.
  - `src/chart/` — charts, drawn from the values Office caches in each chart part (nothing is
    recalculated). `read.ts` reads DrawingML charts (bar/column incl. 3D, line, area, pie,
    doughnut, scatter, bubble, radar) and chartex (box & whisker only) into a model; `draw.ts`
    lays it out like Office (title, legend, auto axis scale with ~5% headroom) as SVG without
    ids. Used by the PPTX frames (`render.ts`) and Word (`docx/charts.ts`: docx-preview leaves a
    chart as an empty sized box; its parsed drawings are matched to the XML in order), and
    Excel (`xlsx/drawings.ts` reads a sheet's cell anchors; the viewer draws charts in overlay
    layers over the grid, not re-rendered on scroll; chart sheets are fitted to the screen; both
    print). Kinds it can't draw keep the placeholder. `test-files/make_xlsx_charts.applescript`
    builds the Excel sample (Excel's scripting needs `chart wizard`, not `set source data`).
  - `src/ooxml.ts` — zip/XML/relationship helpers shared by the XLSX and PPTX readers.
- `test-files/` — sample documents; `make_samples.py` regenerates the synthetic ones.
  `make_xlsx_samples.applescript` builds XLSX samples with Microsoft Excel itself (installed on
  this Mac); `excel_text_dump.applescript` prints the text Excel displays per cell, to compare
  with the viewer's formatting. `make_pptx_sample.py` (python-pptx) + `pptx_resave.applescript`
  and `make_pptx_native.applescript` make decks that PowerPoint has saved, plus PowerPoint's PDF
  of each as the reference rendering. PowerPoint asks once for access to `test-files/`.
  `word_to_pdf.sh` opens a .docx in Word and saves Word's PDF of it (checks edited files).
  In dev, a page can POST a file it built to `/__dev-save?name=x` (vite.config.ts); it lands in
  `test-files/out/` for checking in Word/Excel/PowerPoint (open with `open -a`, which needs no
  sandbox prompt).

**Wide and short screens:** bottom bars and editing toolbars keep their buttons within 600 px in
the middle of a wide screen. A short screen (height < 480 dp, a phone held sideways) gets a 48 dp
top bar (`appBarHeight()`), lower web bars (`@media (max-height: 480px)`), no status bar in the
viewer, and no top bar at all while the keyboard is up; home's buttons sit side by side. Content
stays clear of a side camera cutout (`WindowInsets.safeDrawing`). Test on the phone with
`adb shell wm size 2340x1080` (sideways) or `wm size 1600x2560` + `wm density 320` (tablet), then
`wm size reset` / `wm density reset`; a sideways simulation puts the cutout on the top edge, which
a real phone held sideways doesn't.

**How edits are saved:** the shell owns the Save button and dialog (`ViewerActivity`); an editor
reports unsaved changes with `OfficeBridge.setDirty`. On Save the shell calls
`window.officeSave(mode)`; the editor builds the file, re-reads it, and streams it back in base64
chunks (`web/src/save.ts` → `beginSave`/`writeChunk`/`finishSave`). `Saving.kt` writes it to a
temporary file, checks the format's signature, then either replaces the original (backing it up
first and restoring it if the write fails) or saves a copy through the system's save picker and
reopens the copy. Files lent read-only ("Open with") can only be saved as a copy. In a desktop
browser there is no shell: the editor offers a download instead.

**How bytes reach the viewer:** not through the bridge. The document is served at
`https://appassets.androidplatform.net/doc/current` and the page `fetch()`es it. The bridge only
returns metadata (`getDocument()` → `{name, format, mime, size, url}`). The URL honours HTTP
`Range`, and the PDF viewer reads through it in 256 KB pieces, so large PDFs aren't held in
memory whole. Quirk: for a Range request the WebView skips to the range start itself but reads
to the end of the stream it is given; see `EndingAt` in `DocumentWebView.kt`.

## Rules that come from the PRD

- No `INTERNET` permission, no network requests, no analytics. The WebView refuses every URL that
  isn't served by the app itself.
- No AGPL or commercial-only dependencies. Record each new library's licence.
- User-visible strings exist in English and Indonesian: `res/values` + `res/values-in` for native,
  `web/src/i18n.ts` for web.
- Never overwrite an original file until the new one is written and re-parsed (applies from M5).

## Build and run

Gradle needs a JDK it supports; the system default (27) is too new, so use Android Studio's:

```bash
export JAVA_HOME="/Applications/Android Studio.app/Contents/jbr/Contents/Home"
./gradlew :app:installDebug && ./gradlew --stop
```

`preBuild` runs `npm run build` in `web/` (needs `npm ci` there once, and `npm` on PATH).

Release build (`./gradlew :app:assembleRelease` → `app/build/outputs/apk/release/`,
`:app:bundleRelease` → `.aab` for Google Play): code shrinking is on, so test a release build
on the phone before publishing (`adb install -r …/app-release.apk`; uninstall first if the phone
has a build signed with a different key). Signing reads `keystore.properties` in the project root
(copy `keystore.properties.example`; git-ignored, as are `*.jks`). Without it the release build
falls back to the debug key, which must never be published. Check which key signed an APK with
`apksigner verify --print-certs` (in the SDK's `build-tools/`).

Web-only iteration in a desktop browser, with a file picker instead of the bridge
(`.claude/launch.json` has the same server as `web-viewers`). In dev, `?file=` opens a file
directly, e.g. `http://localhost:5173/?file=/@fs/<repo>/test-files/sample.docx` (add `&edit` to open
in edit mode, as a new document does):

```bash
cd web && npm run dev
```

Device debugging:

```bash
adb logcat -s OfficeEditorWeb          # the web viewers' console output
adb shell am start -a android.intent.action.VIEW -t application/pdf \
  -d "content://..." com.officeeditor  # simulate "Open with"
```

The WebView is inspectable from `chrome://inspect` in debug builds.

If `adb install` fails with `INSTALL_FAILED_VERIFICATION_FAILURE`, Play Protect rejected the build
and hid its prompt (the installer is `adb`). The owner has to allow it on the phone (Developer
options → "Verify apps over USB"); don't change that setting from here.
